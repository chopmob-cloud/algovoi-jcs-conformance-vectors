# guard_keystone_v1 (the keystone record is admitted under the input-bounds profile)

A provenance / precondition binding: it shows the keystone was produced over inputs the
substrate-guard gate admits. This is **not a chain link** (unlike settlement/refund/PEF), it is an
acceptance proof that the deterministic input-bounds gate, which runs before canonicalisation,
ACCEPTS the keystone record under a published profile.

```
profile_ref = "sha256:" + SHA-256(JCS(profile))      # the bounds in force (substrate_guard default)
keystone record  ->  within { max_bytes, max_depth, max_object_keys, max_array_length,
                              max_string_length, max_total_nodes, number_safety }  ->  ACCEPT
```

Reuses the `substrate_guard_v1` default profile (the published `profile_ref`) and the keystone
record. The bound checks are pure structural metrics (byte length, depth, keys, array length,
string length, node count, integer safety), computed identically in Python and Node, so the
ACCEPT verdict is reproducible. No new hashing primitive.

Run:
```
python verify_guard_keystone.py    # pip install rfc8785
node   verify_guard_keystone.mjs   # npm install canonicalize
```
PASS 3/3, Python and Node byte for byte. `guard_keystone_trace.json` is regenerated by
`generate_guard_keystone.py`.
