# 8-implementation cross-validation attestation -- PEF v1 -- 2026-05-30

This document attests the byte-for-byte cross-validation of the
**`pef_v1` Payment Evidence Frame vector set** across **eight
independent JCS RFC 8785 implementations in eight programming languages**
on 2026-05-30.

**Result: 64/64 byte-for-byte agreements.**

Each vector validates two hashes in sequence:
1. `sha256(JCS(receipt))` == `expected_receipt_hash`
2. `sha256(JCS(preimage))` == `expected_frame_id`

This proves that the PEF `frame_id` derivation discipline is
implementation-portable under the canonicalisation pin
`urn:x402:canonicalisation:jcs-rfc8785-v1`.

## What this proves

Every `frame_id` in the `pef_v1` vector set reproduces byte-identical from
eight independent runtime + library combinations. This establishes:

1. **PEF frame_id derivation is implementation-portable.** A downstream
   implementer in any of the eight languages, using any of the eight
   independent JCS libraries, derives the same `frame_id` from the same
   PEF inputs. The `frame_id` is a byte-deterministic global identifier for
   a payment lifecycle event, verifiable across any runtime.

2. **Both hash layers are portable.** `receipt_hash = sha256(JCS(receipt))`
   and `frame_id = sha256(JCS(preimage))` are both independently validated
   across all eight implementations. A verifier in any language can check
   the receipt has not been tampered with (via `receipt_hash`) and the frame
   has not been tampered with (via `frame_id`).

3. **All five PEF claim types are covered.** The discipline holds for
   `payment_admission`, `payment_settlement`, `payment_cancellation`,
   `payment_refund`, and `composite_verdict` -- the complete AlgoVoi
   agentic-payment lifecycle.

4. **PEF composes cleanly with the prior receipt-stack attestation.** The
   `receipt` objects in `pef_v1_001`--`pef_v1_008` match the field shapes
   validated in the [`2026-05-25-8-impl-5-format-cross-validation`](2026-05-25-8-impl-5-format-cross-validation.md)
   attestation. PEF is an additive wrapper: the underlying receipt hashing
   discipline is unchanged; PEF adds the `frame_id` layer on top.
